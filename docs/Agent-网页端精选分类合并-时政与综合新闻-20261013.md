# 网页端精选分类合并：时政 + 综合新闻 → 一个 tab

> 日期：2026-10-13 ｜ 范围：`yxzc` 元见站点（运行态源码目录）
> 面向：接手本仓库的其他 Agent / 后续维护者

---

## 一句话

网页端（`/` 精选 与 `/all` 全部动态）顶部筛选栏里原本并排的 **「时政」** 和 **「综合新闻」** 两个 tab，已合并为一个 **「时政与综合新闻」** tab；点它一次列出两类内容。**公开接口（API / RSS / MCP）不受影响，仍是 13 个类别。**

---

## 1. 需求与背景

- **需求（小麒）**：把元见产品网页端精选界面顶部的「时政」和「综合新闻」合并成一个板块。
- **位置确认**：位于 `apps/web/app/routes/home.tsx` 顶部、由 `apps/web/app/features/feed/Filters.tsx` 的 `CategoryTabs` 渲染的那一排 pill tab；数据源是 `packages/contracts/src/taxonomy.ts` 派生的 `CATEGORY_KEYS`（来自 `industry/taxonomy.ts` 的 13 个类别）。
- **为什么不是简单改标签**：两个 category 是**数据层真实存在**的两类（`current-affairs` 时政 / `general-news` 综合新闻），AI 结构抽取仍在分别归类。只改显示名会出现两个同名 tab，且过滤只能命中一类。所以「合并」= **一个 tab + 该 tab 一次筛出两类**。

## 2. 设计取舍（重要，其他 Agent 先读这段）

仓库里原本已有一套「类别合并」机制 `site/site.ts` 的 **`PUBLIC_CATEGORIES.merge`**，但它的定位写得很明确：

> `PUBLIC_CATEGORIES`：**公开接口（API、RSS、MCP）里和网页不同的类别**。上线后不要改：接口参数和订阅地址里有类别的 key。

改它会**改动客户已经在用的接口参数**（属于接口语义变更，按 `site/site.ts` 约定要升 `interfaceVersion`），而小麒这次限定的是**「网页端」**。因此：

- ✅ **新增一套只作用于网页的合并配置** `WEB_CATEGORIES`，公开接口保持原样（实测仍为 13 类）。
- 两套配置互不干扰：`PUBLIC_CATEGORIES` 管 API/RSS/MCP，`WEB_CATEGORIES` 管网页筛选栏与列表筛选。

## 3. 改动清单

| # | 文件 | 改动 |
|---|---|---|
| 1 | `site/site.ts` | **新增** `WEB_CATEGORIES = { merge: { "general-news": "current-affairs" } }`（网页端类别合并配置；key=被并入的类别，value=并入的目标类别） |
| 2 | `packages/contracts/src/taxonomy.ts` | **新增**：`WebCategoryKey`、`WEB_CATEGORY_KEYS`（合并后的 tab 列表，12 项）、`webCategoryMembers(key)`（一个 tab 覆盖哪些真实 category）、`webCategoryLabel(key)`（tab 名，类别名用「与」拼接）、`toWebCategory(category)`（旧链接兜底）；顶部注释补一句 |
| 3 | `packages/backend/src/publication/items.ts` | `categoryCondition()` 由「`p.category = 单值`」改为按 `webCategoryMembers` 展开（成员 1 个仍走等值，多个走 `IN`）。⚠️ 这是**网页筛选**用的谓词，`/api/site/timeline`、`/api/site/pool`、`/api/site/groups/.../reports` 都走它 |
| 4 | `apps/web/app/features/feed/Filters.tsx` | `filterOptions` 改用 `WEB_CATEGORY_KEYS` + `webCategoryLabel`；`filterKey`、`ActiveFilters` 改用 `toWebCategory` |
| 5 | `tests/public-categories.test.ts` | 网页端那条断言从「按 `CATEGORY_KEYS` 逐类」改为「按 `WEB_CATEGORY_KEYS` + 成员集合」；顶部注释同步更新（原文把「网页筛选合并类别」写成 failure case，已更正） |

**未改**（有意保留）：

- 公开接口：`PUBLIC_CATEGORIES`、`PUBLIC_API_CATEGORY_KEYS`、`toPublicApiCategory`、分类 RSS、MCP 的 `category` 参数 —— 一律不动。
- `industry/taxonomy.ts` 的 13 个类别定义本身（`current-affairs`、`general-news` 都还在，`CATEGORY_KEYS` 仍 13 项）。AI 结构抽取照旧分别归类，只是网页不再分两个 tab。
- 卡片上的类别角标（`FeedItem.tsx` 用 `CATEGORY_LABELS[item.category]`）仍按条目的真实类别显示「时政」或「综合新闻」，属**条目级**信息，不在本次「板块」范围内。
- **日报分节**（`industry/taxonomy.ts` 的 `section`：`时政与社会` / `综合新闻`）未合并，日报仍是两节。见 §7 可选后续。

## 6. 回滚

把 `site/site.ts` 的 `WEB_CATEGORIES.merge` 改回 `{}`，重新 `docker compose up -d --build` 即可恢复「时政」「综合新闻」两个 tab。契约层的 `WEB_CATEGORY_KEYS` / `webCategoryLabel` 等在有合并时才与 `CATEGORY_KEYS` 不同，空合并下行为等同原实现。

## 7. 可选后续（未做，等小麒定）

1. **合并后的 tab 名**：现取「类别名用「与」拼接」的既有惯例，得 **「时政与综合新闻」**。若想更短（如「时政·综合」「要闻」），改 `webCategoryLabel` 或给该 tab 单独起名即可。
2. **日报分节**：日报目前仍是「时政与社会」+「综合新闻」两节（`industry/taxonomy.ts` 的 `section` / `packages/backend/src/reports/edition.ts` 的 `SECTION_ORDER`）。若产品和网页保持一致，可把两类的 `section` 改成同一个（会改变已出日报的分节口径）。
3. **卡片角标**：若希望合并板块内也统一显示「时政与综合新闻」，需要改 `FeedItem.tsx` 的角标（但那是条目级的，会影响 /all、主题页等所有位置）。
4. **公开接口是否也合并**：本可改用 `PUBLIC_CATEGORIES.merge` 一并合并 API/RSS/MCP，但那属于接口语义变更（要升 `interfaceVersion`、改订阅地址文档），本次按「网页端」限定未做。
