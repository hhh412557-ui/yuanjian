# 网页列表排序加权与特色板块隔离（2026-10-13）

> 交接对象：后续接手本项目的 Agent / 开发者
> 改动目录：`D:\永信至诚01\yxzc`
> 起因：产品侧两条反馈 —— ①「全部信息动态」和「精选」点进去第一屏多是时政/综合新闻，AI 与网安占比低；②微盘投递的「威胁情报」把「全部信息动态」的「全部」整页顶掉。

## 1. 问题定位

### 1.1 AI 与网安不靠前

两个列表原来只按时间排：

| 列表 | 取数 | 原排序 |
|---|---|---|
| 「全部信息动态」`/all` | `packages/backend/src/publication/pool.ts` | `ORDER BY p.timeline_at DESC` |
| 「精选」`/` | `packages/backend/src/publication/timeline.ts` | 分组后 `ORDER BY anchor_at DESC`（`anchor_at = min(p.sort_at)`） |

谁新谁在前，与类别无关 → 时政源更新勤，第一屏就被时政占住。

### 1.2 威胁情报整页顶掉其它新闻

- 微型盘投递的信源 `ext-threat-intel`（`industry/sources.json`）走 `POST /api/ingest/items` 入库，`publishedAt` 取文件名日期，成批、且**不经过评分线**（绑源主题走 `listedCondition`）。
- `timeline_at = backfill && published_at ? published_at : discovered_at`（`content/materials.ts:88`）→ 投递批次的时间戳就是入库当刻，永远是最新的。
- 于是这些条目排在「全部」第 1 页最前面，一页 40 条全被占满。

## 2. 改动

### 2.1 站点配置（`site/site.ts`，可调）

```ts
/** 网页列表的类别权重：先分天，同一天内按权重，最后按时间。 */
export const LIST_RANK = {
  ahead: {
    "ai-models": 2, "ai-products": 2,
    "security-advisory": 2, "vulnerability": 2, "threat-intel": 2, "research": 2, "practice": 2,
  },
  behind: { "current-affairs": -1, "general-news": -1 },
};

/** 特色板块（绑源主题的信源）是否进「全部」列表。 */
export const BOARD_SOURCES = { listedInAll: false };
```

排序键 = **北京日 → 类别权重 → 条目时间 → id**，全部倒序。

- 「先分天」是关键：日期分组（桌面端 `DayList` 按天出日期头）不会被拆散，日期头不会来回跳。
- 权重只影响**同一天内**的先后，不改条目显示的日期与时间。
- 公开接口（API / RSS / MCP）与日报**不受影响**，仍按纯时间。

### 2.2 取数层

| 文件 | 改动 |
|---|---|
| `packages/backend/src/publication/items.ts` | 新增 `beijingDay()`、`categoryWeight()`、`listRankOrder()`（读 `LIST_RANK`） |
| `packages/backend/src/publication/boards.ts` | **新增**：`BOARD_SOURCE_IDS`（从 `topics.json` 的 `sourceId` 汇总）、`boardSourceCondition()` |
| `pool.ts` | 无搜索、无类别/标签筛选时套 `boardSourceCondition`（「全部」不再出现绑源板块）；排序改用 `listRankOrder`；`listedCount`、`todayCount` 同口径 |
| `timeline.ts` | `filterSql` 加 `boardSourceCondition`（「精选」同样隔离）；分组排序改「日 → 组内最大权重 → anchor」；`countTimelineDays` 改为全量扫描（原二分假设 anchor 降序，新排序下不成立）；游标 `tl2 → tl3`（多带 `d` 日、`w` 权重，`sortsAfter()` 做四段比较） |

### 2.3 测试

新增 `tests/list-ranking.test.ts`：

1. 同一天内 `vulnerability`、`ai-models`（权重 2）排在 `industry`（0）之前，`current-affairs`、`general-news`（-1）最后；
2. 绑源信源（`ext-threat-intel`）的条目**不在**「全部」里，但在 `category=threat-intel` 的类别页里。

## 3. 特色板块改动后还能在哪里看到

| 入口 | 是否出现微盘投递的威胁情报 |
|---|---|
| 侧边栏「特色频道 → 威胁情报」→ `/topics/threat-intelligence` | ✅（绑源主题页走 `listedCondition`） |
| `「全部信息动态」→ 威胁情报` 类别页 `/all?category=threat-intel` | ✅（有类别筛选时不隔离；前提是模型把条目归到 `threat-intel` 类别） |

想让微盘条目回到「全部」：把 `site/site.ts` 的 `BOARD_SOURCES.listedInAll` 改成 `true` 并重建。

## 5. 已知取舍与后续

- **同一天内**加权：第 1 屏是当天「AI + 网安 → 中性类别 → 时政/综合」。如果产品想要「跨天优先」（所有 AI/网安 都排在最前），日期头会跳动，需要同时改前端分组，暂不做。
- 「精选」页的「威胁情报」类别 tab 目前仍只列**入选**条目（公开源的漏洞/威胁类），不含微盘投递批次。若也要纳入，需在 `timeline.ts` 对绑源主题的类别做 `selectedCondition ∪ listedCondition` 的并集，属独立改动。
- 权重是「排序」不是「配额」：它不会增加 AI/网安条目的绝对数量，只保证同一天里它们排在前面。要真正提高占比，得从信源更新频率和评分线入手。
